Type: grilling
Status: open
Blocked by: none

## Question

What measurable availability, performance, accessibility, privacy, security, backup, recovery, observability, cost, browser, and release-gate criteria must every module satisfy before the First Production Release?

## Comments

- 2026-08-12: This decision must establish, from verified German/EU guidance and counsel where necessary, the legal basis and exact retention period for submitted Quote Requests, consent evidence, and minimal deletion audit records. Without a documented rule, permanent Project or Customer Account deletion removes the Quote Request.
- 2026-08-13: Q156-Q163 approved. A Production Release Gate requires recorded evidence, named approval, and no unresolved release-blocking defect; a successful build or informal browser check is insufficient. Critical defects cover compromise, data loss/exposure, unauthorized access, corrupt commercial handoff, or core outage; High defects prevent a core journey, block a user group, show persistently incorrect configuration/price context, or lack safe recovery. Critical and High block release; Medium requires owner, impact, workaround, and due date.
- 2026-08-13: Release-critical journeys are German editorial browsing; configuration through 3D or fallback; shareable-state recovery; email-OTP sign-in; Project import/save/autosave/reopen; Configuration Revision creation; Shared Revision Link create/revoke; AI-photo request/status/access/deletion; idempotent Quote Request/history; and Project/account lifecycle and deletion. Each receives automated and selected real-browser verification.
- 2026-08-13: Core browse, configure, account, Project, share, and Quote Request journeys target 99.9% monthly availability excluding announced maintenance. Optional AI generation and atmospheric 3D degrade independently. Exhausting the core error budget pauses nonessential feature releases until the cause and highest-value reliability work are addressed; Critical incidents stop risky deployment and activate fallbacks or kill switches.
- 2026-08-13: Releases progress through synthetic preview, production-like staging, migration compatibility, controlled exposure where warranted, and health observation with tested rollback or disable paths. Release Bundle activation, schema migration, application deployment, and provider enablement remain separate reversible actions.
- 2026-08-13: Every production release has one Release Owner who verifies the complete evidence bundle but cannot self-waive specialist rejection. Only a documented business owner may temporarily accept a non-security, non-privacy, non-legal Medium risk with scope, impact, compensating control, owner, expiry, and rollback trigger. Critical/High defects and failed legal, authorization, deletion, backup/restore, or data-integrity gates are not deadline-waivable.
- 2026-08-13: Q164-Q175 approved after a repository audit and German/EU primary-source review. Required verification includes unit, Postgres contract, Adapter contract, Module integration, Playwright critical-journey/browser, deterministic 3D/fallback, automated/manual accessibility, staging, and post-deploy smoke tests. Critical behaviors and failure branches matter more than a global coverage percentage.
- 2026-08-13: A clean locked CI candidate must pass lint/type checks, dependency/secret/license/security scans, tests and migrations, accessibility, build and budgets, browser/render matrices, synthetic deployment, smoke and rollback readiness, and signed artifact/SBOM evidence. The project selects one package manager, removes divergent lockfiles, pins the reproducible graph, and forbids `latest` for production candidates.
- 2026-08-13: WCAG 2.2 AA applies to all public, account, configurator, fallback, photo, sharing, and Quote Request journeys with manual keyboard, focus, dialog, error, zoom/reflow, reduced-motion, contrast, screen-reader, and fallback-equivalence review. - 2026-08-13: Resilience tests cover stale and duplicate work, timeouts and reordered events, partial provider/worker/database/storage failure, lifecycle/deletion states, withdrawn releases, and migration rollback without duplicate external effects or silent corruption. Proportionate load tests run at twice forecast peak and document saturation, degradation, cost, and scaling/kill-switch triggers.

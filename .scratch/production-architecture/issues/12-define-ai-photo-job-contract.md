Type: grilling

What asynchronous states, ownership, quotas, retries, cancellation, retention, consent, moderation, provider references, cost records, storage rules, deletion behavior, and Project associations must the AI-photo module guarantee?

## Answer

The First Production Release uses an application-owned asynchronous Photo Job Module rather than the current synchronous Replicate HTTP request. Only an authenticated Customer Account may request generation. Every Photo Job belongs to exactly one Project and one immutable Configuration Revision, and only the Project owner may view, download, retry, cancel, or delete its artifacts. Guests and Shared Revision Links cannot generate or access Generated Photos.

Requesting a photo checkpoints the caller's expected Working Configuration version and durably creates or reuses its Configuration Revision, Source Capture association, Photo Job, quota reservation, and outbox work in the application before provider execution. A stale or invalid configuration creates no provider side effect. The server derives product facts from the pinned Release Bundle and composes them with an approved Scene Preset through an immutable Prompt Template Release; free-form customer prompts and browser-supplied product facts are excluded.

The First Production Release may capture the 3D canvas in the browser. The browser uploads the Source Capture through a single-use signed URL to designated EU object storage, where the application validates type, dimensions, size, checksum, and ownership. The capture is untrusted visual input and never product or commercial evidence. A later deterministic renderer may replace browser capture without changing the Photo Job Module Interface.

The deep Photo Job Module offers the equivalent of requesting a photo, retrieving a job, listing Project photos, and cancelling a job. It hides orchestration, provider calls, moderation, storage, quota, cost, retries, and callbacks. Customer-visible progress remains waiting, creating, ready, failed, cancelling, or cancelled. Internally the Module distinguishes queued work, uncertain submission, submitted execution, running work, ingestion, moderation, success, failure, cancellation request, cancellation, and expiry so it can recover without exposing provider vocabulary.

The Photo Generation Interface is a real provider seam because Replicate is accepted only through a scoped, revocable processing exception and must remain replaceable. It permits only submitting an approved request, retrieving execution facts, and requesting cancellation. A separate provider webhook ingress Adapter verifies provider-specific signatures. SDK types, provider states, error shapes, output URLs, and execution IDs do not escape these Adapters.

A Photo Job exists before any provider call and survives browser closure, refresh, and device change. Webhooks are verified from their raw payload, protected against replay, deduplicated in a unique inbox, and restricted to monotonic state transitions. The receiver acknowledges quickly and schedules ingestion or follow-up through internal work. Every nonterminal job is also reconciled by provider retrieval because callbacks can be missing, delayed, duplicated, out of order, or incomplete.

An idempotency key identifies one deliberate generation request. Retrying the application command with that key returns the original Photo Job and does not duplicate quota or cost. A deliberate new variant uses a new key and consumes a new quota unit. Each Photo Job may make at most two automatic provider attempts for classified transient failures using capped exponential backoff. Submission uncertainty must reconcile before another attempt can begin; invalid configuration, input validation, safety rejection, cancellation, licensing, and permanent provider errors never retry automatically. Each attempt has an immutable operational and cost record.

A job succeeds only after provider output is downloaded, validated, malware-scanned, checked under the current safety and configuration-integrity policy, stored in EU object storage, and committed as a Generated Photo linked to the exact Configuration Revision. Provider success alone is insufficient. Output containing people, sexual or violent content, hate symbols, prominent third-party branding, or obvious configuration corruption is not shown or retained as a Generated Photo. Staff access to Source Captures or rejected output requires an audited, time-limited support or safety-review purpose. Customer material cannot be used for model training, marketing, or portfolio work without a separate explicit agreement.

Before first use, the customer acknowledges versioned notice of external AI processing, illustrative and potentially inaccurate output, prohibited people/personal/confidential input, retention behavior, and quota use. The application records notice versions and time. This is an acknowledgement unless legal review establishes consent as the correct lawful basis.

Initial configurable customer policy permits two concurrent jobs, five provider-started jobs per rolling 24 hours, and 30 per rolling month. Validation failure does not consume quota. System/provider failure and non-customer-caused safety rejection restore it, while customer cancellation after provider work begins does not. Separate provider-wide daily and monthly budget reservations, alerts, and a kill switch stop new work without losing reconciliation of existing jobs.

Queued cancellation prevents submission. Running cancellation is explicitly best effort: the local job enters cancelling, the Adapter asks the provider to cancel, and late output is discarded and deleted instead of published. The application records actual incurred cost and never changes or deletes the Configuration Revision. Customer-facing state settles only after provider reconciliation or a defined expiry policy.

Generated Photos and minimal provenance remain for the Project lifetime unless individually deleted. Source Captures are deleted seven days after the last dependent terminal job. Provider URLs and staging objects are removed after ingestion or terminal failure and never become customer-facing asset references. Individual deletion removes a photo from the Project gallery; if a deliberately submitted Quote Request has a valid retention basis, it may retain a detached, restricted copy, otherwise the object is deleted. Project and Customer Account deletion follow the previously approved hierarchy.

Every enabled production model is represented by an immutable approved Model Release containing its exact model or deployment version, license review, input/output contract, safety behavior, pricing snapshot, and evaluation evidence. Every attempt records the Model Release, Prompt Template Release, safety-policy version, opaque provider reference, timestamps, outcome, usage/timing evidence, reserved estimated cost, later reconciled billed cost, and input/output hashes. Estimates never masquerade as invoiced cost, and mutable provider `latest` behavior cannot silently enter production.

Replicate is the initial production Photo Generation Adapter by explicit exception to the otherwise strict EU-member-state-only processing rule. Its [published subprocessor list](https://replicate.com/docs/topics/site-policy/subprocessors) identifies United States locations and its public material provides no EU-only processing guarantee, so the architecture must not describe it as compliant with that gate. Its documented one-hour [prediction cleanup](https://replicate.com/docs/topics/predictions/data-retention/) reduces exposure but does not establish complete contractual deletion, and the public API documents no per-prediction delete operation.

Before production activation, procurement and legal must complete the [Replicate production-control gate](19-verify-replicate-production-controls.md): execute and approve the DPA and transfer mechanism, review the current subprocessors and deletion/backup terms, approve the exact model and license, confirm disclosures and lawful basis, and test retention, webhook, cancellation, reconciliation, moderation, cost, and kill-switch behavior. Failure of that gate disables new AI-photo generation without blocking the rest of the First Production Release. The Photo Generation Interface and EU-owned system of record preserve a later provider exit.

A Generated Photo remains an illustrative planning artifact. It may accompany a Quote Request for context, but it cannot establish finishes, dimensions, included items, price, or delivery promise. Those facts come only from the Configuration Revision, Release Bundle, and later Authoritative Quote.
